# CG14 NiFi validación viva

NiFi2.0 se consulta por su API real; se han comprobado tipos/propiedades instalados,
no se importa el ConsumeKafka_2_6 antiguo de1.25 como si fuera compatible.
ConsumeKafka usa Kafka3ConnectionService, Processing Strategy FLOW_FILE y keyUTF8.
ExtractText conserva el CSV, CSVReader con esquema Avro explícito -> ConvertRecord
con JsonRecordSetWriter. ExecuteGroovyScript valida ancho14, fecha UTC real,
identidad/tipo, cinco dominios numéricos finitos y bits de etiqueta. Elimina las
etiquetas de X, conserva raw_record para auditoría y genera ID SHA256 de la clave.

No imputa ni replica features/modelo en NiFi. Lotes inválidos van a PutFile en
volumen state/quarantine, no a inferencia ni a un score0. Cola con backpressure
1000 objetos/16MB; no expira para ocultar fallos. La cuarentena falla ante conflicto,
no sobrescribe contenido previo.

Snapshot exportado del servidor: nifi-flows/cg14_validation_snapshot.json.
Es la etapa en construcción: contiene conectores de integración parados e incluso
placeholders sin configurar; NO se presenta como export final listo para importar.
El snapshot final y recuentos se entregan en CG16/CG20 cuando el flujo drene.
La fuente está marcada lab_fixture: no se pretende haber leído SMB vivo.
