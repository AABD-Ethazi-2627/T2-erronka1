  conservados byte a byte. No se atribuyen al candidato nuevo.

  de validación reutilizada y las cruza con las filas aprobadas de AI4I. No carga modelos,
  no ejecuta inferencia, no ajusta umbrales ni evalúa test.

  `docs/evidence/CG24_current_state_types.json`, SHA-256

  El script exige esa referencia, hash del CSV, split exacto, etiquetas de fuente y conteos
  coincidentes. Usa `float_precision="round_trip"` y `>=`, sin tolerancia.

## Reproducción sin servicios

Usar el entorno de Python3.11 y dependencias de `uv.lock`. En esta ejecución se reutilizó
el intérprete explícito del entorno bloqueado de CG24 (Windows y Fedora); no se alteró.
Conservar el CSV ya generado con el hash indicado, sin regenerar el experimento.
Extraer la referencia con bytes intactos, por ejemplo con Python `subprocess.check_output`
de `git show a4da1d5:docs/evidence/CG24_current_state_types.json` y `Path.write_bytes`.

```sh
python -m scripts.build_cg19_evaluation \
  --validation-csv outputs/cg19-validation.csv \
  --reference-json outputs/cg24-corrected-reference.json \
  --output outputs/cg19-reproduced.json
python -m scripts.create_lab_dashboard --check
python -m unittest discover -s tests -p 'test_lab_dashboard.py' -v
ruff check scripts/create_lab_dashboard.py scripts/build_cg19_evaluation.py tests/test_lab_dashboard*.py
ruff format --check scripts/create_lab_dashboard.py scripts/build_cg19_evaluation.py tests/test_lab_dashboard*.py
git diff --check
```

El primer comando exige una salida nueva. Comparar su JSON con `kibana/cg19-offline.json`;
la reproducción byte a byte se comprobó en Windows y Fedora. El generador sin `--check`
regenera solo su fuente local; ya no publica ni exporta vía API. Los consumidores del
antiguo comando deben importar explícitamente el candidato cuando se autorice.

## Validación ejecutada y alcance

- 12 tests específicos en Windows y Fedora: objetos/referencias, query/contexto, orden/50,
  huecos, bins, igualdad en umbral CSV, guards de evidencia, ausencia/zero, determinismo
  y bloqueo de red durante generación.
- ES9.5.4 aislado en Fedora: contenedor propio `t2-cg19-query-20261021`,
  puerto loopback19219, sin volúmenes/montajes. 60 fixtures sintéticas, dos índices,
  mapping estricto del repo. Tres tests de queries reales pasaron: resumen/filtros/vacío,
  medias horarias/huecos/fuentes y últimos50/desempate/filtro. Se comprobó UUID antes
  de escribir y se rechazaban índices existentes. No hubo API de scoring ni etiquetas en ES.
- Suite completa Fedora: 119 tests, 6 omitidos (3 por bundle de entrega ausente;
  3 de integración ES optativa, ejecutados aparte). `ResourceWarning` de streams AnyIO
  heredado durante la suite: se registra, no se considera consola limpia.
- Vega5.33.0: las tres specs generadas se parsearon/ejecutaron y renderizaron a SVG
  sin warnings (summary1 fila, temperature12 tras transform, wear15). Para summary y
  temperature se sustituyó **solo el transporte Kibana** por las respuestas reales del
  ES efímero; wear usa los valores offline del artefacto. Es render local del spec,
  **no render de Kibana**, importación de saved objects ni prueba del dashboard completo.
- PNG del render local: [KPI con fixtures](CG19_v2_spec_summary.png),
  [temperatura con fixtures y hueco](CG19_v2_spec_temperature.png),
  [heatmap de validación reutilizada](CG19_v2_spec_wear.png).
  No son capturas de Kibana ni datos industriales. La edad del KPI corresponde al instante
  de render, no a una observación actual persistente.
- Accesibilidad: se mantienen tabla y filtros nativos, unidades/textos/denominadores,
  etiquetas numéricas en heatmap y distinción de sensores por trazo. Inspección visual
  del render local realizada. Teclado, lector de pantalla, zoom y reflow en Kibana
  pendientes; no se afirma conformidad WCAG ni equivalencia accesible completa del canvas.
